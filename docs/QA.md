# 검증 기록 · 2026-11-06 · 2.6

## 사용자 Chrome에서 직접 확인

- 2.5.1에서 실제 화면 캡쳐 → 영역 선택(780×305 CSS px) → 미리보기 → 페이지 안 이미지 표시 → 실제 한국어 OCR 완료를 확인했습니다. 가상 안내문의 마감일 2026년 11월 12일, 준비물, 참가비 15,000원, 제출 문장이 편집창에 표시됐습니다. 한글 띄어쓰기 오류는 일부 있습니다.
- 2.6.0 업데이트와 문장 드래그 → 선택 도우미 클릭 → 원래 페이지 안 편집창 표시를 확인했습니다. 선택한 날짜·준비물·비용·제출 문장이 유지됐고 새 탭을 열지 않았습니다.
- 2.6.0에서 실제 캡쳐(800×315 CSS px) → iframe 없는 좌우 배치 확인 창 → 이미지 전체 보기/돌아가기 → OCR 응답 표시를 확인했습니다. 주요 버튼과 원문/편집창이 한 화면 안에 유지됩니다. 선택 강조색이 있는 영역에서 OCR 누락도 관찰했으므로 정확도 보장을 뜻하지 않습니다.
- 같은 Chrome에서 팝업의 PDF 업로드 → 새 문서 정리 화면 → 샘플 결과를 열어 입력·결과·주요 버튼이 전체 페이지 스크롤 없이 한 화면에 표시되는 것을 확인했습니다. 캡쳐 결과 확인 탭과 문서 정리 화면을 열어 두었습니다.
- 사용자 파일 PDF는 도구의 로컬 URL 제어 제한으로 최종 수동 확인하지 않았습니다.

## 자동 검사

- `npm test`: 날짜 유효성, 가상 문서 5종, JSON/multipart API, Worker PDF/image content block·파일 시그니처·IP 제한·연도 없는 날짜 보존 등 18개 통과.
- `npm run check`: manifest 진입점과 popup/workspace/OCR 문서 자산 참조 검사.
- `tests/browser.mjs`: 실제 압축해제 확장의 샘플 → 결과 → 목록 → 편집/확인/완료/필터 → 새로고침 초기화. 문서 정리 화면을 1440×683, 1280×600, 1024×640에서 검사해 전체 페이지 세로 스크롤 없이 주요 버튼이 보이는지 확인. 390px 화면 가로 넘침 없음.
- 같은 테스트의 페이지 도우미/캡쳐 UI는 **runtime과 캡쳐 이미지 응답을 모의 처리**합니다. 버튼 드래그·메뉴 비겹침·선택 전달·입력창 제외·업데이트 연결 오류 안내·500×250 크롭·캡쳐 OCR 호출 없음·이미지 직접 분석 메시지·iframe 없는 확인 창·닫기/Esc를 검사합니다.
- 1200×240 가로 이미지와 240×1200 세로 이미지의 비율 보존(contain)·경계와 전체 보기/돌아가기를 검사하고 스크린샷을 직접 검토합니다.
- `tests/global.mjs`: 테스트용 복사본에 HTTP/HTTPS 접근을 미리 부여한 격리 Chromium. 실제 동적 등록·서로 다른 사이트 자동 표시·실제 content runtime → background → 페이지 내 드래그 확인 창·새 탭 없음·원문 유지·Esc 닫기·전역 모드 끄기 후 등록/UI 제거. 권한 제거 API는 모의 처리하며 네이티브 승인/회수 UI를 검증한 것은 아닙니다.
- `tests/offscreen.mjs`: 실제 content runtime → background → offscreen 문서 → 응답. 잘못된 이미지 거부·동시 읽기 거부·새 탭/세션 이미지 없음·처리 문서 닫기. **OCR 엔진만 테스트 문자열로 대체**하며 OCR 정확도 증거가 아닙니다.
- `tests/pdf.mjs`: 별도 Chromium의 로컬 PDF에서 로고와 메뉴 표시. 사용자 PDF 내용/OCR 전체를 검증하는 테스트는 아닙니다.

## 수정 근거

2.5의 캡쳐 후 iframe 표시가 사용자 Chrome에서 빈 창으로 남았습니다. 2.6은 확인 UI를 페이지 안 Shadow DOM에 직접 그리고 OCR만 offscreen 문서로 분리합니다. 사용자가 보는 결과는 외부 문서 로딩에 의존하지 않습니다. 같은 확인 UI를 문장 드래그에도 사용합니다. 캡쳐/드래그 내용을 세션 저장소에 전달하던 경로와 공개 iframe 리소스는 제거했습니다.

## 남은 검증 / 팀원 후속

- 실문서·복잡한 표·스캔 PDF·흐린 이미지·대용량 파일의 OCR 정확도.
- 여러 실제 사이트와 제한 페이지, 네이티브 사이트 권한 승인/회수, PDF 파일 접근, 재시작, 네트워크 단절.
- Cloudflare Worker의 multipart→Claude 경로는 개인정보 없는 합성 PDF로 실제 확인해 HTTP 200과 구조화된 결과를 받았습니다. 사용자 PDF/이미지와 표 문서의 실제 인식 정확도는 아직 검증하지 않았습니다. 영구 저장·알림·OAuth/Calendar는 미구현이며, 고정 샘플은 정확도/성공률 근거가 아닙니다.
- `npx wrangler deploy --dry-run`은 16개 정적 자산과 `RATE_LIMITER`(10/60초), `ASSETS`, `CLAUDE_MODEL` 바인딩으로 통과했습니다. 승인 후 운영 배포했으며 `/`와 `styles.css`는 HTTP 200, `/api/status`는 설정된 모델을 반환, `/api/analyze` CORS 사전 요청은 204를 반환했습니다. 개인정보 전송과 API 비용을 피하려고 실제 분석 POST는 실행하지 않았습니다.
- 직접 PDF/이미지 입력으로 변경한 현재 Worker 코드는 이 QA 갱신 시 운영 배포하지 않은 상태입니다. 로컬 dry-run과 모의 API 테스트는 별도로 실행합니다.
- `npm run test:browser`는 Playwright Chromium 파일 설치 후에도 `libatk-1.0.so.0` 시스템 라이브러리가 없어 실행되지 않았습니다.
- macOS 스크린리더 전체 사용성과 극단적인 화면 확대는 별도 확인이 필요합니다.
